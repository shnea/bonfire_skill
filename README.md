# Bonfire Skill

**Bonfire 개발 스킬과 초기 기준 문서를 구성하고, 프로젝트 기준을 내보내거나 가져오는 스킬입니다.**

`$bonfire`를 호출하면 대상 프로젝트의 기존 지침을 확인하고, 두 기본 스킬과 프로젝트별 기준을 구성합니다. 요구사항·기술 선택·결정 기록은 대상 프로젝트에 남아 Git으로 함께 관리됩니다.

## 설치

스킬 폴더는 [skills/bonfire](skills/bonfire/SKILL.md)입니다. Codex의 skill-installer에 다음처럼 요청할 수 있습니다.

```text
$skill-installer https://github.com/shnea/bonfire_skill 저장소의 skills/bonfire 스킬을 설치해줘.
```

다른 스킬 지원 도구에서는 `skills/bonfire` 폴더 전체를 해당 도구의 설치 방식에 맞춰 가져옵니다. 내부의 `assets`도 함께 필요합니다.

## 사용

대상 프로젝트에서 다음처럼 요청합니다.

```text
$bonfire 이 프로젝트에 Bonfire 기본 구성을 적용해줘.
```

특정 경로를 지정하거나, 이미 적용한 프로젝트의 누락 파일을 보완하도록 요청할 수도 있습니다.

스킬은 다음 구성을 배치합니다.

| 경로 | 역할 |
| --- | --- |
| AGENTS.md | 프로젝트 시작 안내 |
| skills/workflow/ | 요구사항 정리·구현·검증 절차 |
| skills/golden-path/ | 핵심 기준·14개 영역·스킬 연결·결정 이력 |

기존 AGENTS.md와 프로젝트 기록을 보존하고, 같은 이름의 다른 스킬이나 충돌하는 지침이 있으면 해당 부분을 확인합니다. 다시 호출해도 기존 기준을 초기 상태로 덮어쓰지 않도록 지시합니다.

기준 문서와 스킬 본문은 모두 프로젝트의 `skills/`에 둡니다. `.agents` 쓰기가 제한된 환경에서도 프로젝트 기준을 수정할 수 있습니다. 시작 안내는 `AGENTS.md`에서 이 경로를 연결합니다.

## 프로젝트별 사용

설치한 `bonfire`는 초기 구성·누락 파일 보완·프로젝트 기준 내보내기와 가져오기를 담당합니다. 구성 후의 일반 개발 작업에는 프로젝트 안의 `workflow`와 `golden-path`를 사용합니다. 프로젝트의 golden-path에서도 내보내기·가져오기를 요청할 수 있습니다.

프로젝트마다 별도의 기준 문서를 갖기 때문에, 한 프로젝트의 기술 선택이나 예외가 다른 프로젝트에 적용되지 않습니다. 프로젝트별 변경은 설치된 스킬의 원본에도 자동 반영되지 않습니다.

## 프로젝트 기준 내보내기·가져오기

코드를 제외하고 지금까지 정리한 기준을 문서 묶음으로 옮깁니다. 새 환경에서 같은 프로젝트를 이어가거나, 다른 프로젝트를 시작할 때 참고 자료로 사용할 수 있습니다. 파일 생성·검사·병합은 이 스킬을 읽는 에이전트가 수행합니다.

### 내보내기

원본 프로젝트에서 요청합니다.

```text
$bonfire 지금까지 정리한 이 프로젝트의 기준을 내보내줘.
코드와 실행 명령은 제외하고 다른 환경의 golden-path에서 이어서 사용할 수 있게 해줘.
```

기본 위치는 `exports/bonfire-<프로젝트명>-<날짜와 시각>/`입니다. 다른 경로를 지정하거나 ZIP으로 요청할 수 있습니다. 설치용 템플릿 대신 현재 프로젝트에서 발전시킨 기준을 읽으며, 원본 기준은 수정하지 않습니다.

| 포함하는 내용 | 제외하는 내용 |
| --- | --- |
| 목적·요구사항·기술 선택·제약·예외·결정 이유 | 소스 코드·코드 예제·실행 명령·스크립트·설정 파일 |
| 확정·미정·보류·해당 없음, 빈 작성 자리, 사용자 추가 영역 | 빌드 산출물·로그·비밀값 |
| 독립적인 이해에 필요한 참조 문서 | AGENTS.md·workflow·스킬 본문·실행 자원·관리 절차 |
| 추가 스킬의 출처·역할·조건·원본 상태 | 추가 스킬 설치·활성화 권한 |

golden-path 폴더 전체를 그대로 복사하는 방식이 아닙니다. 필요한 참조 내용을 함께 모으고 내부 링크를 조정합니다. 문서에 섞인 코드·명령은 설명으로 바꾸되 요구사항과 계약은 보존합니다. 누락·변환 내역을 명시하고, 가져오기에 필요한 세부 조건을 요약으로 생략하지 않습니다.

```text
BONFIRE-EXPORT.md       형식 버전·출처·파일 목록·제외/변환·누락
context/
  core.md              현재 핵심 기준
  project-rules.md     영역 색인
  domains/             영역별 기준
  decisions.md         결정 이유와 이력
  skills.md            추가 스킬 연결 정보
  supporting/          필요할 때 포함하는 참조 문서
```

### 가져오기

대상 프로젝트에서 묶음의 경로와 용도를 지정합니다. 기본 구성이 없으면 동봉 템플릿을 배치한 후 기준을 가져옵니다.

```text
$bonfire ../project-context/의 기준 묶음을 이 프로젝트로 가져와줘.
같은 프로젝트를 새 환경에서 이어가는 것이니 기존 결정과 상태를 복원해줘.
```

```text
$bonfire ../project-context/의 기준 묶음을 새 프로젝트의 참고용으로 가져와줘.
기존 결정은 제안으로 두고 이 프로젝트에서 채택한 것만 확정해줘.
```

| 용도 | 가져온 뒤 상태 |
| --- | --- |
| 같은 프로젝트 이어가기 | 기존 결정·상태·이유를 복원. 새 환경의 경로·연동·검증 상태는 별도 확인 |
| 다른 프로젝트의 출발점 | 원본은 참고 자료로 보존하고 후보는 제안으로 기록. 대상의 확정 기준은 유지 |

변경할 기존 기준을 먼저 백업하고 항목별로 병합합니다. 충돌은 임의로 덮어쓰지 않으며, 반복해서 가져온 동일 내용은 중복 추가하지 않습니다. 추가 스킬 연결은 기본적으로 `준비 중`으로 가져오고 대상에 실제로 있는 연결만 확인해서 사용합니다. 코드·명령·추가 스킬은 자동 설치하거나 실행하지 않습니다.

가져온 결과에는 백업 위치, 적용한 내용, 충돌·누락, 환경에서 다시 확인할 사항을 표시합니다. 이 기능은 프로젝트 기준을 복원하며, 제품 코드나 실행 환경을 복원하지는 않습니다.

원본 Bonfire의 `golden_path`와 설치본의 `golden-path`는 동일한 **문서 묶음 형식 v1**을 사용합니다. 기존 구성의 이름을 유지하며 중복 폴더를 만들지 않습니다. 예전 설치본은 이 저장소의 최신 스킬로 업데이트한 뒤 사용할 수 있고, 기존 프로젝트 기준은 초기화하지 않습니다. 세부 규칙은 [내보내기·가져오기 절차](skills/bonfire/assets/template/skills/golden-path/references/transfer.md)에 있습니다.
